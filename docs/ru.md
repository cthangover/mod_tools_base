# Основа инструментов — общий набор окон-редакторов

`tools_base` — библиотека для авторов модов, которые пишут окна-редакторы. Сама она не добавляет ни окон, ни кнопок на тулбар. Игроку не нужно ставить её отдельно: каждый редактор, которому она нужна, подтягивает её как зависимость.

## Кто её использует

Редакторы сцен, сценариев, карты мира, интерактивов и освещения, конструктор сцен, экспорт каталога, редакторы предметов и персонажей, редакторы RPG-карт и тайлсетов и инструменты схем (`schema_tools`).

## Что она даёт инструменту

- **`ToolUi`** — общий вид окон-инструментов: кнопки, поля, секции, разделители, строка статуса, переведённые подписи (`ToolUi.Tr`). Сама рамка окна (`ToolWindow`) остаётся в `ui_base`.
- **Виджеты** — `ModFileSelector` (выбор записываемого мода и файла в папке), `FilteredList`, `CollapsibleSection`, `BackgroundCanvas` (фон сцены с масштабом), `DragHandle`.
- **Файлы** — `ModFileService` (чтение и запись файла по пути внутри мода, только для модов-папок), `ModResourceService`, `SceneFileService`/`SceneBackgroundService` (логические сцены и их фоны), `LocaleFileService` и `PropertiesText` (правка текстов `.properties` на всех языках мода без потери комментариев и порядка).
- **Редакторы сущностей** — `EntityEditorWindow`, `EntityDocument`, `EntityField`: список с поиском и форма с текстами на всех языках, картинками и полями JSON. На них построены редакторы предметов и персонажей (см. `docs/concepts/tools.md`).
- **Формы по схемам** — редакторы полей, построенные по аннотациям `schema_base` (скаляры, списки, словари, локализованные тексты). Поле `pick` предлагает значения, которые держат сущности другого вида (допустимые типы экипировки слота); поле `stages` — это пронумерованные шаги задания, у каждого текст на всех языках мода (`StageFieldEditor`, реализует `ITextFieldEditor` вместе с другими редакторами текстов).
- **Переименование id** — `EntityRename` и `EntityRenameDialog`: id сохранённой сущности меняется через **Переименовать…**, которое до записи перечисляет все файлы, где он назван. Ссылки в редактируемом моде переписываются; тот же id в других модах только перечисляется и не меняется. **Отменить переименование** возвращает файлы побайтово. Окно сначала сохраняет несохранённые правки. Поиск ссылок — `SchemaReferenceScanner` в `schema_base`; он находит только ссылки, которые описывают схемы и DSL.
- **Договорённости между инструментами** — через `IScenarioResourceEditor` одно окно просит редактор сценариев открыть файл по адресу внутри мода; `IScenarioTextTarget` и `ScenarioTextTargets` направляют вставку из палитры команд в последний сценарий, который был в фокусе. Редакторы снимают регистрацию, когда их окно закрывается.

- **Записи других модов** — список может показывать записи зависимостей мода. Правка такой записи пишется патчем в редактируемый мод (`patches/<вид>/<мод>.json`), файл владельца не меняется. Значки у полей показывают, откуда значение (ваш патч, патч другого мода, наследование); **↺** сбрасывает поле.
- **Поля только для чтения** — `EntityField.Locked` показывает поле, которое нельзя менять, для значения, которое сущность вычисляет из другого места (здоровье персонажа при наличии статов).
- **Контракт `IMapPickupEditor`** — кнопка «Place on map» в редакторе предметов просит редактор RPG-карт открыться с подобранным объектом.

## Как написать на ней инструмент

Зависимость `tools_base>=1`, реализация `IToolProvider` (строит окно) и, для пункта в наборе инструментов, `IToolBoxButton`. Игра сама находит их в сборках модов, запись в манифесте не нужна. Пишите файлы только через `ModFileService`, тогда упакованные моды останутся только для чтения.

## Зависимости

`ui_base`, `schema_base`. Набор тестов `isolation` (`--itest=tools_isolation`) проверяет, что библиотека работает без единого окна-редактора.
